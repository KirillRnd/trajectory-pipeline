# CR3BP: исходный код и начальные аппроксимации

Отдельный компонент комплекса, перенесённый из `D:/MATLAB/ipm/CR3BP`.
Импорт 8 ноября 2026: **23 неизменённых Python-файла, 12 блокнотов только
с кодом**, 7 модулей формул без запуска обучения или графиков.
Происхождение и SHA256 — `source_manifest.json`. `/import-source` в нём —
чтение исходного каталога через Docker, не новая внешняя зависимость.

- `source/` — исторические Python-исходники. Многие выполняют обучение,
  загрузку внешних массивов или построение графиков прямо при запуске.
  Их не импортировать в рабочий процесс как обычную библиотеку.
- `notebooks/` — сохранённые непустые кодовые ячейки без текстовых ячеек,
  вывода, изображений и метаданных. Обучение из них не воспроизводится
  без исходных датасетов и PySR; эти зависимости не добавлены в среду.
- `approximations/` — выбранные исходные определения функций/констант
  L1, L2, L3, L4 v2/v3, S3; `c_families.py` — неизменённый `formulas.py`
  с функциями C1/C2. Формулы не переобучались и не подправлялись.
- `trajectory_pipeline.cr3bp.seed` — самостоятельный адаптер шести
  приближений с проверкой массового параметра, демонстрационного диапазона,
  конечности результата и явным статусом `approximation_only`.

Не перенесены статьи, PDF/TeX/DOCX, изображения, таблицы/датасеты, pickle,
модели/журналы обучения, checkpoints, резервные копии, редакторские QA и
экспортёры статей, MATLAB-скрипт рендера статьи, оболочка `run_many.sh`
для повторных запусков обучения, пустой `Untitled.ipynb`.

## Самостоятельный вызов

Из корня репозитория, только Docker:

```sh
docker compose run --rm -T --entrypoint python pipeline -c "from trajectory_pipeline.cr3bp import seed; print(seed('L1', 0.8))"
docker compose run --rm -T -e PYTHONPATH=/workspace --entrypoint python pipeline components/cr3bp/check_approximations.py --output runs/cr3bp_check/verification.json
docker compose run --rm -T --entrypoint python pipeline -m unittest discover -s tests -p test_cr3bp_component.py -v
```

Возвращаются `[x,y,vx,vy]`, период, μ, параметр семейства и происхождение.
Система вращающаяся барицентрическая; расстояние первичных тел, суммарный
гравитационный параметр и угловая скорость равны 1. Это **не SI/TDB**.

| Семейство адаптера | Параметр и исходный демонстрационный интервал | μ |
|---|---|---|
| L1 | x=L1−d, d от 0.00001 до 0.2734644, L1=0.836915131427382 | 0.012150584460351 |
| L2 | x=L2+d, d от 0.0001 до 0.3464867, L2=1.155682161024677 | 0.012150584460351 |
| L3 | x от −1.99906 до −1.00607 | 0.012150584460351 |
| L4_v2 | a от 0.1 до 2.79 | 1/82 |
| L4_v3 | a от 0.01 до 2.69 | 1/82 |
| S3 | a от 0.005 до 4.19 | 0.012150584460351 |

Названия L4 сохранены из файлов: геометрия начальной точки определяется
исходными x1(a), x2(a), а не догадкой по названию. Демонстрационные интервалы
не являются сертификатом точности. Модуль формул S3 принимает μ, но диапазон
обучения по μ не восстановлен: адаптер пока разрешает только исходное
демонстрационное значение. Для C1/C2 фиксировано μ=3.0393890e−6; область
пригодности и поведение у резонансов ещё не проверены, поэтому общего
адаптера `seed` для них пока нет. Доступны исходные функции
`components.cr3bp.approximations.c_families.v2_C1/T_C1/v2_C2/T_C2`.

## Что подтверждено

Четыре проверки в Docker прошли: контрольные суммы и отсутствие выводов
блокнотов; точность извлечения определений; ограничения адаптера;
независимое интегрирование шести характерных точек.
Числа сохранены в `reports/cr3bp/verification.json`. Дрейф интеграла Якоби
не больше 3.84e−12; невязка положения после приближённого периода
от 0.00282 до 0.02695 в нормированных единицах. Малый дрейф Якоби проверяет
интегрирование, но не качество периодического замыкания. Все результаты
остаются начальными приближениями, **ни один не принят как точная
периодическая орбита**. В C1/C2, Halo и остальные исследовательские семьи
эта проверка не переносится.

Связь с `solve`, корректор периодических орбит, перевод в физическую
систему/эпоху и сшивка с межпланетной ПСИ ещё не реализованы. Земля–Луна
присутствует как исходная CR3BP-параметризация; Луна не возвращается в
список целей общего межпланетного метода.

## Повторение импорта

`import_source.py` читает исходный каталог, ничего в нём не исполняет,
пишет новый каталог в `runs/` и отказывает при уже существующем выходе.
Например, с дополнительным read-only bind исходной папки в `/import-source`:

```sh
docker compose run --rm -T --volume D:/MATLAB/ipm/CR3BP:/import-source:ro --entrypoint python pipeline components/cr3bp/import_source.py /import-source runs/cr3bp_import_new
```

Результат требует проверки перед заменой сохранённого компонента. Для
штатного использования исходный внешний каталог не нужен.
