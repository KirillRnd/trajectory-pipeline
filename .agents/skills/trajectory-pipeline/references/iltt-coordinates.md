# Переключение координат оптимизации ИРТ

**Сопряжённые переменные имеют приоритет.** Нельзя ограничивать, проецировать
или отбрасывать полученное решение только потому, что чистые аппроксимации
ILTT его не представляют. Переключение должно сохранять текущие сопряжённые.

`solver.irt_coordinates` задаёт `"costates"` (по умолчанию), `"iltt"` или
последовательность, например `["costates", "iltt", "costates"]`.
Оба режима решают одну краевую задачу ИРТ. В режиме ILTT оптимизируются
шесть параметров `q=[dm,j,Omega,omega,kappa,lambda]`; Якобиан получается
цепным правилом из вариационных уравнений и производной отображения ILTT.

## Сохранение решения при переключении

Используется локальное отображение

`p = F_ILTT(q; r0,v0) + delta_p`, где `p=[p_r,p_v]`.

Если чистое отображение восстанавливает сопряжённые, поправка нулевая.
Иначе параметры возвращаются к объявленной опорной точке, а `delta_p`
сохраняет **исходные** сопряжённые точно. Во время оптимизации ILTT эта
поправка фиксирована; она не добавляет оптимизируемых переменных.
Граница R относится к локальным параметрам аппроксимации, а не к допустимым
сопряжённым или физическим решениям. Её не расширять ради переключения.

Сохранённое представление включает начальное нормированное состояние,
опорные параметры, текущие параметры, границу R и **обязательную поправку**.
Шести чисел q недостаточно для восстановления скорректированного
представления. Обратный переход всегда использует полный набор данных.
Канонические сопряжённые продолжают сохраняться в обычных полях траектории.

В момент смены координат не меняются дата, физическая длительность,
источники орбит, масса/двигатель и граничные состояния. Не вычислять новую
длительность через `T_a(lambda,kappa)`: эта связь относится к раннему входу
ILTT, а здесь lambda/kappa — координаты корректора. Оптимизация длительности
остаётся отдельной операцией. При последующих итерациях q также не следует
выдавать за измеренные элементы конечной орбиты или фактическую витковую
дальность уже скорректированной траектории.

## Вызовы

Переключение на сохранённой проверенной ИРТ:

```sh
docker compose run --rm pipeline recoordinate-irt <irt-folder> --coordinates costates iltt costates --output runs/coordinate_switch
```

Совместно с переходом к полным эфемеридам:

```sh
docker compose run --rm pipeline reconcile-irt <early-irt-folder> --sources configs/apophis_full_sources.json --coordinates costates iltt costates --output runs/full_with_switch
```

Для нового `solve-irt` задать `solver.irt_coordinates` в JSON миссии.
Опорные параметры берутся из `solver.iltt_resolved.x_corrected`. Для
сохранённых решений без этой записи необходимо явно задать
`solver.iltt_coordinate_reference`: шесть параметров локального представления.
Нельзя подбирать новую угловую ветвь обратно из заданного времени.

API: `ILTTCoordinates(initial_normalized, reference)`, `from_costates`,
`to_costates`, `jacobian`, `record`, `restore`; корректор `correct_shooting`
принимает `coordinates` и `iltt_reference`. В диагностике каждого шага
сохраняются режим, невязка, параметры, поправка и ошибка обратного преобразования.
Внешняя приёмка по-прежнему требует независимого интегрирования и проверки
границ. Завершение оптимизатора само по себе не означает принятия решения.

## Поддержка и ограничения

Подключено к корректору центральной ИРТ, `solve-irt`, раннему sweep,
`recoordinate-irt` и `reconcile-irt`. На одной локальной карте сохраняется
короткое/длинное семейство аппроксимации (граница lambda=0,75). Это не запрет
коротких ветвей и не ограничение канонических сопряжённых.

Корректоры избытка, Пазова, физической ПСИ и свободного времени пока не имеют
этого нелинейного переключателя. Не объявлять его доступным там только
потому, что миссия содержит соответствующий параметр solver. Их прежние
режимы работы в сопряжённых остаются. При застревании локальной карты можно
явно вернуться в `costates`, затем заново привязать ILTT к новому решению.

## Проверка разных целей и дат

[Матрица 45 случаев](../../../../reports/coordinate_matrix_v1.md): 15 постановок,
по три даты (исходная и ±90 суток), 13 целей включая Цереру. Приняты 42 ИРТ:
20 в ILTT, ещё 22 после переключения на сопряжённые; одна из последних
потребовала следующую положительную ветвь. Три пролётных Сатурна не приняты.
Апофис на всех трёх датах дополнительно пересогласован с полными эфемеридами.
Это проверка ИРТ, не ПСИ/топлива и не оптимизации свободной длительности.

При отказе ILTT обязательно пробовать сопряжённые с отдельным бюджетом.
Передавать последние численные сопряжённые (если они доступны) либо исходное
приближение, сохраняя их статус «непроверенные». При отказе начального
согласования допускается приближение той же выбранной по дате ILTT-ветви;
время остаётся выведенным из ILTT. Не подменять это принятым ILTT и не выбирать
ветвь обратно по произвольно назначенному времени. Выход выведенной эпохи за
покрытие эфемерид допускает экстраполяцию и сам по себе не требует смены ветви.

`python -m trajectory_pipeline.coordinate_matrix --output runs/<new>` в Docker
запускает первичную матрицу с обязательными обоими режимами; `--resume`
сохраняет завершённые строки. В Linux-процессах действует отдельный таймер,
прерывающий также внутреннее интегрирование старого ILTT. Дополнительная ветвь
и переходы Апофиса сохранены отдельными запусками в архиве отчёта.

Продолжение этих 42 ИРТ до физической ПСИ проверено отдельной серией:
[маршруты и приёмка](accepted-irt-routes.md),
[построчный отчёт](../../../../reports/accepted42_psi_v1.md).
Число принятых ИРТ не подменяет число физических ПСИ.
