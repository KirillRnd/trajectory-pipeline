# Явные источники орбит и переход ИРТ

`Mission.orbit_sources` — словарь по телам. Неуказанное тело использует полные
локальные эфемериды (прежнее поведение). Название тела остаётся `Apophis`;
`ApophisNew` — имя набора элементов, а не другого небесного тела.

```json
"orbit_sources": {
  "earth": {"kind": "kepler", "preset": "EarthSimple"},
  "apophis": {"kind": "kepler", "preset": "ApophisNew"}
}
```

- `Apophis`: элементы до встречи, эпоха 01.03.2029 TDB.
- `ApophisNew`: элементы после встречи, эпоха 01.05.2029 TDB.
- `EarthSimple`: прежняя автономная кеплерова модель Земли.
- `{"kind":"ephemerides"}`: полноценные локальные таблицы / KIAM.
- Вместо `preset` можно передать `elements` с полями `epoch_jd`, `a_m`, `e`,
  `i_deg`, `node_deg`, `peri_deg`, `M_deg`, `mu_m3_s2`.
  Допускаются эллиптические орбиты, центр Солнце, ECLIPJ2000, время TDB, SI.

Набор выбирается явно и не переключается по дате. `ApophisNew` распространяется
по Кеплеру и назад до встречи: это модель целевой послевстречной орбиты для
раннего поиска, а не утверждение о фактическом положении Апофиса до встречи.
Исходные выгрузки с полной точностью сохранены в `data/orbits/`.
Метаданные результата включают элементы и SHA256 исходной выгрузки.
Математическая область распространения кеплеровой модели не означает её
физическую точность на всём интервале. `EarthSimple` также является старой
аппроксимацией, заметно отличающейся от актуальной Земли.

## Маршрут без эфемерид в ранней части

```sh
docker compose run --rm pipeline solve-irt configs/apophis_new_early.json --output runs/new_source_early
docker compose run --rm pipeline reconcile-irt runs/new_source_early/irt --sources configs/apophis_full_sources.json --output runs/new_source_full
```

Первая команда: дата → фаза → положительные ветви → ILTT → длительность → ИРТ.
Обе орбиты здесь кеплеровы; чтение таблиц не требуется. Та же настройка
поддерживается в раннем `sweep-irt --design`. Исходная граница R сохраняется.
Выбор источника входит в контракт миссии и привязку кеша ILTT.

Вторая команда принимает проверенную ИРТ **без добавочного импульса**,
сохраняет дату и длительность, заново вычисляет обе граничные позиции и
векторы скорости, масштабирует сопряжённые и корректирует краевую задачу.
При необходимости дробит переход по границам; промежуточная смесь не
выдаётся за решение на полных эфемеридах. Приёмка — независимое LSODA и
проверка контракта против заново полученных границ. В `summary.json` записаны
сдвиги границ, все попытки и достигнутый параметр; только `completed_stage`
и `irt/` означают завершённый переход. Отказ не отменяет исходную ИРТ.

Далее передавать **новый** `new_source_full/irt` в `departure`, затем Пазов/ПСИ.
Освобождение длительности — отдельная операция следующих этапов; переход
источника сам по себе время не оптимизирует. Не подменять его новым холодным
ILTT и не менять только метку в старом результате.

Обычный `solve` автоматически включает этот маршрут для ранних кеплеровых
источников: `early_irt` → `resolved_irt` → `physical`. Сохраняются исходный
запрос, журнал пересогласования, хеш входа и отдельный результат каждого этапа.
`--resume` проверяет принятые узлы и продолжает физическую часть. По умолчанию
физические источники — полные эфемериды обоих тел;
`solver.physical_orbit_sources` задаёт явную альтернативу. Равенство этой
настройки ранним источникам явно оставляет кеплерову модель на позднем этапе.
Холодное ребро графа вызывает тот же контроллер.
Перенос непосредственно физической ПСИ командой `reconcile-irt` не реализован.
