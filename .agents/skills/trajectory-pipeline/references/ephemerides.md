# Компонент ephemerides

Часть единого [траекторного комплекса](../SKILL.md).

Работать из корня проекта внутри Docker. Windows Python не запускать.
Публичный интерфейс: `trajectory_pipeline.ephemerides.Ephemerides`.
Возвращаемые состояния — геометрические SI, ECLIPJ2000, JD TDB и явно заданный
центр. Эфемериды по умолчанию читаются офлайн; пакет KIAM не редактировать.

`docker compose run --rm pipeline coverage <body> [<body> ...]`
показывает локальное покрытие. Проверять весь интервал миссии и опорных орбит.
В связке с РБ начало интервала раньше `launch_tdb` на время пролёта от НОО;
при скрутке конец позже `launch_tdb + tof_days` на длительность захвата.
Проверять покрытие и для преобразования локальных участков в общую
гелиоцентрическую траекторию, а не только для внешней ПСИ.
Экстраполяция разрешена и не отсекает кандидатов, шаги корректора или
интервалы освобождения длительности. За таблицей используется крайний
полином Эрмита; скорость — его производная. За нативным диапазоном KIAM
продолжение строится по двум крайним суточным состояниям, не меняя пакет.
`evaluation_record` и аудит конфигурации сохраняют исходный диапазон и
признак экстраполяции; это информация, а не запрет или критерий отказа.
Локальные таблицы возмущающих тел также допускают экстраполяцию.
У ряда внешних планет нативные JPLEPH данные — барицентр
системы; не называть их центром планеты без проверки каталога.

Явное расширение через Horizons:
`docker compose run --rm ephemerides cache <body> --start <date> --stop <date> --step "12 h"`.
Обычный сервис `pipeline` работает без сети и с данными только для чтения;
сервис `ephemerides` разрешает сеть и запись в локальный каталог эфемерид
только для явно запрошенной загрузки.
Уточнение внутри имеющейся таблицы: та же команда с `--refine` и меньшим шагом.
Для расширения существующей таблицы CLI cache не перезаписывает каталог:
использовать `ephemerides.download(..., cache=<новый каталог в runs>)`,
проверить таблицу и только затем заменить рабочую копию с сохранением прежней.
После выбора даты и угловых ветвей проверять покрытие выведенных длительностей
и интервала их освобождения. Проверка прежнего фиксированного времени недостаточна.
Новый объект регистрировать по однозначному Horizons ID в общем каталоге.
Подбирать шаг по динамике: например, тесное сближение Апофиса требует
существенно более частой таблицы, чем спокойный гелиоцентрический участок.

Сохранять исходный ответ, параметры, SHA256 и таблицу. Оценивать ошибку
интерполяции по независимым отложенным эпохам; уплотнение без измерения
ошибки не доказывает точность. Не смешивать состояние центра с барицентром,
UTC с TDB или экваториальные оси KIAM с эклиптическими осями проекта.
Ошибка интерполяции относительно Horizons не является оценкой неопределённости
долгосрочного прогноза орбиты астероида. Выборочная сверка не доказывает верхнюю
границу ошибки во всех точках интервала.

Земля–Луна–Солнце использует отдельную неизменяемую таблицу в
`data/lunar_ephemerides/`, создаваемую общей функцией `prepare_lunar_ephemerides`.
Таблица связана с результатом хешем. Полное поле включает прямое и косвенное
ускорения Луны и Солнца; его сверяет `verify_kiam_gravity` по нативному JPLEPH.

Явные альтернативы таблицам — [кеплеровы источники и переход ИРТ](orbit-sources.md). Не выбирать до-/послевстречный набор автоматически по дате старта.
