# Угловая скрутка и подбор длительности под запас топлива

Доступно через `solve` с `orbital_maneuvers.arrival.kind=spiral`; работает
с импульсным отлётом и раскруткой. Расчёты выполнять в Docker. Тяга
поперечная тормозящая, F/c постоянны. Исторические `control_type`,
`mUsed`, `m_compensation` и закон УММП не подмешиваются.

## Флаги и сохранённый запрос

Пример готового поиска: `configs/angular_capture/mars_fuel6.json`.

```sh
docker compose run --rm -T pipeline solve configs/angular_capture/mars_fuel6.json --output runs/mars_capture_search
docker compose run --rm -T pipeline verify-orbital runs/mars_capture_search
docker compose run --rm -T pipeline render-orbital runs/mars_capture_search --output output/pipeline/mars_capture_search
```

Для исходной конфигурации без поиска флаги задаются так:

```sh
docker compose run --rm -T pipeline solve configs/orbital_modes/mars_impulse_spiral_dry60.json --output runs/mars_angular --capture-mode angular --capture-phase-reference periapsis --capture-half-width-deg 120 --capture-search-widths-deg 110 120 140 180 --capture-fuel-budget-kg 6 --spacecraft-fuel-budget-kg 40 --capture-max-days 1800
```

Это пример другой сетки, не утверждение о приёмке каждого её элемента.
`--capture-search-widths-deg` включает поиск; без него рассчитывается одно
окно. `--capture-mode continuous` явно включает непрерывное торможение
новым интегратором. Не совмещать его с ненулевыми угловыми настройками.
При отсутствии `capture_control` сохраняется прежний режим для старых
постановок и артефактов.

CLI принимает **градусы**, JSON хранит **радианы**. Переопределения входят
в сохранённый `mission.json`, запрос и его хеш. Не редактировать метаданные
готовой траектории для изменения параметров двигателя или управления.

| Поле arrival | CLI | Смысл |
|---|---|---|
| `capture_control.mode` | `--capture-mode` | `continuous` или `angular` |
| `capture_control.phase_reference` | `--capture-phase-reference` | `periapsis` или `fixed_axis` |
| `capture_control.half_width_rad` | `--capture-half-width-deg` | Полуширина θ₀ |
| `capture_control.eccentricity_slope_rad` | `--capture-eccentricity-slope-deg` | θ(e)=θ₀+k·e, по умолчанию k=0 |
| `capture_control.phase_offset_rad` | `--capture-phase-offset-deg` | Смещение центра окна от фазовой опоры |
| `duration_search.half_widths_rad` | `--capture-search-widths-deg` | Заранее объявленный набор, 1–32 уникальных значения |
| `arrival_propellant_budget_kg` | `--capture-fuel-budget-kg` | Максимальный расход на скрутку |
| `spacecraft_propellant_budget_kg` | `--spacecraft-fuel-budget-kg` | Максимальный суммарный расход КА от исходной орбиты |
| `max_capture_days` | `--capture-max-days` | Полная длительность скрутки с начальной пассивной дугой; по умолчанию 2000 суток |

Поиск требует хотя бы одного явного ограничения топлива. Если заданы оба,
выполняются оба. Сухая масса проверяется независимо. Топливо внешнего РБ
не входит в бюджет КА, как и в остальных составных режимах проекта.

`periapsis` следует за текущим вектором эксцентриситета. При e ниже
`circular_eccentricity` (по умолчанию 1e−8) он явно отказывает: для почти
круговой орбиты выбирать `fixed_axis`. Эта ось задаётся направлением
перицентра конечной орбиты и поворачивается вместе со всей скруткой при
сшивке; это не неподвижная глобальная ось X. Для круговой конечной орбиты
она задаёт выбранный конечный радиус. Ориентация конечной орбиты свободна.

Допустима полная ширина θ=π при k=0 либо θ(e) в диапазоне
[0.001, π−0.001] на эллиптическом e∈[0,1]. Неверные параметры отклоняются,
а не обрезаются. Вырожденные почти нулевые окна не входят в поддержанный
режим. Домен фазовой опоры и закон направления не переключаются неявно.

## Расчёт и приёмка

Обратный интегратор строит движение от конечной орбиты и массы,
используя долготу и угловой момент. Включения/выключения определяются
событиями; вне окна расход нулевой. Прямая проверка использует физическое
время и угловую скорость и **заново находит события**. Она не получает
обратное расписание в качестве принудительного управления.

Каждый кандидат отдельно согласуется с физической ПСИ: масса на стыке,
положение и вектор скорости меняются вместе. Согласуется также отлёт.
`launch_tdb` и `tof_days` сохраняют принятую семантику межпланетного участка:
конец скрутки позже эпохи входа в сферу на её фактическую длительность.
Полная временная шкала включает отлёт, межпланетный участок и скрутку.

После сшивки проверяются запрос/двигатель, оба стыка, конечная орбита,
сухая масса, бюджеты, независимые уравнения ПСИ/KIAM и массовый баланс
скрутки по **суммарной длительности активных дуг**, а не по одному
`burn_start_s`. В метаданных прибытия сохраняются `control`, повернутая
`reference_axis`, `arcs`, `active_duration_s`. Графики используют эти дуги.

`capture_search.json` сохраняет все исходы. Результат поиска лежит в
`summary.selected_folder`; это самостоятельный принятый расчёт с собственным
запросом. Команды `verify-orbital` и `render-orbital` понимают корень поиска.
Выбирается минимальная **полная длительность миссии** среди принятых
кандидатов. Это дискретный поиск по объявленной семье, не доказательство
глобального минимума и не индивидуальная подгонка закона для каждого тела.

Отказы различаются: `capture_duration_limit`, `capture_budget_constraint`,
`capture_control_domain`, несогласованный межпланетный участок или отказ
независимой приёмки. Если принятого кандидата нет, возвращается
`no_verified_feasible_capture_candidate`, `status=partial`, без выбранного
результата. Это не доказательство физической недостижимости.

`--resume` сохраняет результаты уже завершённых кандидатов, проверяет их
идентичность запросу и приёмку успешных. Не перезапускает неудачные точки
бесконечно. Для нового набора или бюджета использовать новый выходной каталог.

## Самостоятельный модуль и свидетельства

API: `backward_capture(..., control={...}, max_days=...)`, затем
`orient_capture` и `forward_capture(..., control=..., reference_axis=...)`.
В самостоятельном вызове без межпланетной части нельзя заявлять приёмку
составной миссии. Общий поиск подключается через `run_orbital_pipeline`.
