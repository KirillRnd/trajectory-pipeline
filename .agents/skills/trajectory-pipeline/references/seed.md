# Компонент seed

Часть единого [траекторного комплекса](../SKILL.md).

Работать из корня проекта внутри Docker. Windows Python не запускать.
Постановка и формат — [документация](../../../../trajectory_pipeline/README.md),
текущие области применимости — [состояние](../../../../PIPELINE_STATUS.md).

ИРТ: `docker compose run --rm pipeline solve-irt <mission.json> --output <new-run>`.

### Основной вход: сначала дата, затем угловая дальность

Для новой центральной межпланетной задачи штатный режим — `solver.irt_entry="date"`
(по умолчанию). `tof_days` можно не задавать. Последовательность обязательна:
дата старта → синодическая фаза цели относительно отправления → допустимые
ветви `a_OM` с целым k → преобразования и сопряжённые ILTT → согласование
орбиты и фазы цели на полученную дату прибытия → длительность через `T_a`.
Основа — сохранённый `ILTT/transfer_legacy.py`, функции исходного toolbox;
эфемериды и перевод времени используют общие единицы комплекса.

`solver.iltt_branch` — номер ветви по возрастанию положительной угловой
дальности, начиная с 0; `iltt_max_abs_k` по умолчанию 5. Допускаются все
положительные λ: 0,75 — граница выбора аппроксимации в `T_a` и
`get_initial_adjoint`, а не фильтр допустимости ветви. При λ<0,75 используются
имеющиеся формулы малой дальности; скрытого зажима λ к 0,05 нет.
Наличие формул не гарантирует сходимость для любого тела: сопряжённые
строятся из опорных κ=0,72 и 1,52; в a_OM знаменатель содержит log(κ),
так что почти одинаковые размеры орбит требуют особого внимания.
Каталог положительных a_OM не является доказанно полным перечислением
всех коротких решений. Численные отказы выбранных ветвей не доказывают
отсутствия других физических траекторий.
При отказе сначала проверять `initial_transform_saturated`: исходная оценка
Δm (геометрический параметр ζ, не масса КА) может выйти за внутреннее
обрезание R, обнуляя столбец якобиана. Базовая граница ±0,598199639 подобрана
автором для умеренно нелинейной области; её сохранять. Отдельную попытку с
ослаблением задавать `solver.iltt_dm_limit`, например 0.8 или 1.0, без удаления
ограничения. Параметр одинаково передаётся в обрезание R, ограниченный корректор
и итоговые сопряжённые, входит в привязку кеша. Предел должен оставаться меньше
1/cos(0.642), но математическая определённость не гарантирует сходимость.
Общий корректор работает внутри выбранной области для насыщенных оценок,
а также после неудачи обычного `hybr`.
Маршруты и численная область сохраняются в `correction_attempts`:
j∈[−30,30], κ∈[0,1;10], Δm внутри указанного интервала, λ внутри выбранной
положительной ветви. Это ограниченный поиск, не физические границы метода.
Сходимость оптимизатора без малой невязки не является приёмкой.
Пробный шаг ограниченного корректора за покрытием эфемерид отклоняется TRF
с уменьшением доверительной области; экстраполяции нет. Начальная точка и
конечная эпоха должны быть допустимы. Число отклонений сохраняется как
`rejected_coverage_trials`, в том числе в сообщении о несогласовании.
[Аудит 108 остановок раннего sweep Апофиса](../../../../reports/apophis_early_iltt_failure_audit.md).
[Разбор Апофиса и полная последовательная цепочка](../../../../reports/apophis_classical_204_v1.md):
204/140 кг, два СПД-50М; старты 15.06 и 01.07.2029 дошли до физической ПСИ.
Февральская дата и некоторые соседние летние даты пока не согласуются.
Отказ выбранной ветви не заменять
произвольной пристрелкой от интерполяции границ. `iltt_budget_s` ограничивает
согласование. `iltt_duration_bounds_days`, если задан, только фильтрует
выведенную длительность, не используется для обратного подбора λ.

`solver.iltt_resolved` сохраняет фазу, варианты λ/k, выбранную ветвь, начальные
и уточнённые параметры, сопряжённые и полученную длительность. Это служебный
результат; не заполнять вручную. В полном расчёте исходная постановка сохраняется
в `entry_request.json`, разрешённая — в `mission.json`, происхождение —
в `iltt_entry.json`. Все последующие аудиты относятся к разрешённой миссии.
CLI дополнительно сохраняет `cli_request.json` с исходным вводом и флагами
до назначения границ времени. Мягкий бюджет ILTT проверяется между вызовами
модели; при серийной работе нужен и жёсткий предел процесса, как в search.

`solver.irt_entry="fixed_time"` оставлен как явный специальный режим:
длительность задаётся пользователем, ILTT даёт только начальные сопряжённые.
Не называть его полным входом ILTT по дате. Старые серии с таким обратным
подбором не являются проверкой нового входа. Сохранённые старые расчёты при
возобновлении не переводить на другую длительность автоматически.

Матрица JSON-миссий: `sweep-irt <matrix.json> --output <new-run>`.
Проверенный результат указан в `summary.json:last_result`; не предполагать,
что после возобновления он всегда называется `irt/`.
Для лунного ИРТ команда сама продолжает земное поле до Земля–Луна–Солнце.
Его `--resume` сохраняет принятый двухтельный вход и точки гравитационного пути.

Начальная скорость:
`docker compose run --rm pipeline departure <verified-result> --output <new-run>`.
Продолжение checkpoint: добавить `--resume`.
Режимы миссии: `fixed_vector`, `fixed_norm`, `bounded_norm`, `free`.
На границе шара проверять ККТ и знак множителя, внутри — p_v(t0)=0.
Команда `departure` означает продолжение по начальной скорости ИРТ,
а не физический участок от НОО с РБ. Для него использовать `solve` с
`parking_departure` через [trajectory-pipeline](../SKILL.md).
В составной миссии начальная скорость на конечном радиусе и истинный v∞
связаны энергией гиперболы; не подменять одно другим. Готовое ИРТ/ПСИ
используется как начальное приближение для нового согласования интерфейсов.
Лунное начальное приращение отсчитывается от опорной круговой орбитальной
скорости, это не гиперболический избыток у Земли.

## Ранний sweep КЛО + ИРТ

Для поиска дешёвых дат до физических моделей:

```text
docker compose run --rm pipeline sweep-irt configs/apophis_spd50m_204.json --design configs/apophis_early_sweep_2027_2033.json --output runs/apophis_early_new
```

С `--design` первый файл — одна миссия; без него сохранён прежний режим матрицы.
Дизайн задаёт `start_tdb`, `stop_tdb`, `step_days`, `max_duration_days`,
`max_abs_k`, `workers`, `worker_timeout_s`, `iltt_budget_s`, `irt_budget_s`.
Даты — TDB. λ = φ/(2π) — витковая дальность, k — индекс расслоения.
Каждая дата и кандидат рассчитываются независимо: дата → фаза → положительные
λ(k) в заданном диапазоне k → длительность КЛО → согласование ILTT → ИРТ.
Начальная оценка и исправленная длительность должны укладываться в горизонт.
Начальный фильтр может отсечь кандидата, который после коррекции вошёл бы в
горизонт: это ограниченный каталог, а не полный поиск физических решений.

Выбор на каждой дате — по размерному J = ½∫|u|²dt, м²/с³, среди независимо
проверенных ИРТ. Безразмерные J между датами с разными масштабами не сравнивать.
Начальная скорость совпадает со скоростью планеты; добавочный импульс, Пазов,
ПСИ, физический расход и освобождение времени в этом режиме не выполняются.
Сохраняются `catalogue.json`, `results.json`, `summary.json` и отдельные случаи;
нет кандидата в горизонте и отказ ILTT/ИРТ — разные исходы.
`--resume` требует неизменных входов, кода, эфемерид и среды; готовые отказы
автоматически не пересчитывает. Для фиксации образа передавать
`TRAJECTORY_IMAGE_ID` через `docker compose run -e TRAJECTORY_IMAGE_ID`.

Апофис 2027–2033, шаг 7 суток, горизонт 1095,75 суток: 366 дат,
115 рассчитанных кандидатов, 7 принятых ИРТ, 108 отказов ILTT;
251 дата без кандидата в начальном горизонте.
[Результаты и воспроизведение](../../../../reports/apophis_early_sweep_2027_2033_v1.md).

После выбора окон уплотнять сетку дат отдельной серией с шагом 1 сутки;
проверенные исходные ИРТ можно непосредственно передавать в `departure`,
затем `pazov` → `psi` → освобождение длительности. На каждой дате сохранять
физическую ПСИ даже при неуспехе последующей оптимизации времени. Оценку J
раннего ИРТ не подменять расходом топлива физической ПСИ.
Решение пользователя для суточной серии Апофиса от 12.11.2026: использовать
исходные семь траекторий и базовую границу Δm, без её ослабления.

ИРТ минимизирует квадратичное управление без физического расхода топлива.
Не выдавать его массу/пиковое ускорение за допустимую ПСИ.
Сравнивать доступные ветви начальных приближений: первое сошедшееся решение
может быть чрезмерно дорогим. Сохранять сведения о выборе ветви.

Принимать решения по независимому пересчёту, допускам в метрах/м/с и
трансверсальности. Для Луны также требуется полное поле и проверка сближений
с Землёй/Луной. Промежуточную гравитационную модель не считать готовой миссией.
