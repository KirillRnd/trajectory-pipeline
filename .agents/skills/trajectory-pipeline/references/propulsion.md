# Компонент propulsion

Часть единого [траекторного комплекса](../SKILL.md).

Использовать общий код из корня проекта внутри Docker. Windows Python не запускать.
Читать физическую модель в [документации](../../../../trajectory_pipeline/README.md)
и актуальные нерешённые случаи в [состоянии](../../../../PIPELINE_STATUS.md).

`docker compose run --rm pipeline pazov <verified-irt-or-departure> --output <new-run> --alpha <target>`
достигает фиксированного предела ускорения и смешанного функционала; по умолчанию α=1.
`docker compose run --rm pipeline psi <verified-pazov-result> --output <new-run>`
вводит массу на сглаженном функционале и затем достигает точного α=1.
Возобновлять тем же входом и `--resume`. Последний результат брать из summary.

Для исторического закона УММП после точной гелиоцентрической ПСИ с центральным
полем запустить `docker compose run --rm pipeline ummp <verified-psi> --output <new-run>`.
Продолжение вводит зависимые от мощности тягу и компенсированный массовый
расход. На каждом шаге решаются сопряжённые уравнения с градиентом двигателя и
заново подбираются времена переключений. Принимать УММП при
`reached_fraction=1` и успешном `verify-ummp <last_result>`. При остановке
сохранить последнюю проверенную долю и причину из `continuation.json`.
Порог отключения 200 Вт требует отдельной гибридной сшивки сопряжённых.
[Команды и контроль Апофиса 156 кг](../../../../trajectory_pipeline/README.md#переход-от-пси-к-уммп).

Эти команды строят ПСИ отдельного участка. Для связки с РБ или конечной
орбитой применять `solve` с `parking_departure`/`capture` по
[trajectory-pipeline](../SKILL.md) и его
[инструкции интерфейсов](planetary-interfaces.md).
Контроллеры заново согласуют границы внешней ПСИ, полный вектор скорости
и остаточную массу; принятую ПСИ до центра тела нельзя объявить выходом
на орбиту. Закон скрутки — поперечное торможение с теми же F/c и переменной
массой. Требуемая Δv РБ и расход ЭРДУ — разные результаты; без массовой
модели РБ его топливо не входит в расчёт.
Раскрутка на отлёте и импульсный захват реализованы через `orbital_maneuvers`
и общий `orbital_pipeline.py`. Независимый выбор способов манёвра и правила скачков скорости/
массы описаны в [матрице сочетаний](planetary-interfaces.md#сочетания-отлёта-и-прибытия).
Не выдавать существующую скрутку за импульсный захват и не обращать её
во времени как готовую раскрутку без физического закона расхода.
В новом интерфейсе масса задаётся на исходной орбите: после раскрутки
меньшая масса передаётся внешней ПСИ. Для химического захвата используется
его собственный c; это топливо перевозится во время перелёта. В режиме
заданного начального вектора корректоры обязаны брать его из запроса,
а не оставлять скорость старого приближения.

Базовый аппарат ПСИ задаётся в миссии: начальная/сухая масса, постоянные F и c.
Управление Пазова — локальный `components/pazov`, KIAM используется неизменённым.
Промежуточный больший предел явно имеет `hardware_limit_reached=false`.
При β<1 масса — proxy; её нельзя сообщать как физический расход.
Массу можно вводить до завершения снижения тяги, но конечная проверка обязана
подтвердить фактические F, c, β=1 и α=1.

По умолчанию промежуточные модели могут расходовать больше конечного
запаса топлива при сохранении положительной массы. Сухая масса обязательна
при приёмке точной физической ПСИ. Явный
`solver.intermediate_allow_below_dry_mass=false` возвращает ограничение
и на промежуточных этапах. ИРТ остаётся безмассовой; граница Δm в R —
численная область преобразования, а не топливный бюджет КА.

На конечном функционале использовать явные переключения активных/пассивных дуг.
Проверять независимый пересчёт, все граничные условия и ККТ, массу выше сухой,
точные 0/F, нули и знаки функции переключения и баланс расхода F/c по времени
активных дуг. `verify_kiam_psi` сверяет уравнения и управление с Fortran;
для Луны добавляет независимую N-body проверку поля.

Сохранённый частичный путь не является готовой ПСИ или доказательством
недостижимости. Не повышать тягу под прежним именем миссии ради сходимости:
иной аппарат — отдельная явно названная конфигурация и отдельный результат.
При неудаче исследовать диагностику корректоров и ветвь; не запускать
неизменённые циклы в надежде на иной исход.

Для продолжения набора уже принятых ИРТ использовать
[маршруты серии и критерии физической приёмки](accepted-irt-routes.md):
последовательная и совместная масса/тяга, раннее/позднее освобождение времени,
точные дуги в сопряжённых и R-координатах, независимые переносы между датами.
